## 二、功能

### 2.1 按年级 / 教材配置学习内容（新建档案时选择）

建档面板里选：**年级（一～六年级）**、**教材版本**、**英语起点（一年级起点 / 三年级起点）**，面板底部会实时显示"本次范围：中文 X 字 · 拼音 Y 条 · 英语 Z 词"。

映射规则（只会包含**本年级及以下**内容）：

| 科目 | 规则 |
|---|---|
| 中文 | 一年级→第 1 组（200 字），N 年级→第 1..N 组 |
| 拼音 | 声母/韵母/整体认读（一年级）+ 第 1..N 组音节 |
| 英语 | 三年级起点：N 年级→教材 3..N 年级单元（N<3 时按三年级基础单元）；一年级起点：按 N 年级递进 |

- 档案随时可在「我的 → 学习内容 → 修改」或「学习」页右上角调整年级，**旧记录不会删除**，只是不再产生新卡。
- 教材版本会随档案保存并显示（首页/学习页标签、「我的」页），当前词库按课标 + 人教版 PEP 主题整理，选其它版本时按同年级通用内容匹配，UI 有说明。
- 老版本档案首次打开会自动按年级补齐学习范围（一次性迁移）。

### 2.2 六项练习

| 科目 | 模式一（认读） | 模式二（输出） |
|---|---|---|
| 英语 | **认词**：看英文 →「认识/不认识」→ 显示中文释义 → **二次确认** | **拼写**：看中文 + 首字母提示 → 输入英文 → 判对错（编辑距离≤2 算"差一点"） |
| 中文 | **认字**：看汉字 →「认识/不认识」→ 拼音/部首/笔画/释义/组词 → 二次确认 | **听写**：听发音（0.4–1.4 倍速可调）→ 纸上写 → 看答案自评 |
| 拼音 | **认读**：看拼音（声母 b / 韵母 ai / 音节 zhōng）→「认识/不认识」→ 例字 + 例词 + 读音 → 二次确认 | **拼写**：看汉字 → 输入拼音字母 + 点选**声调** → 字母对声调错判"差一点" |

拼音两项的交互与结构跟英语完全一致（同一套卡片、二次确认、三档判定、同一套遗忘曲线），只是把"中文释义"换成"例字例词"、把"输入单词"换成"输入字母 + 声调"。

### 2.3 记忆调度（艾宾浩斯）

**跨天间隔**：`1 → 2 → 4 → 7 → 15 → 30 → 60 → 120` 天。

**当天循环（重要）**：艾宾浩斯的经典复习节点本身就包含「5 分钟 / 30 分钟 / 12 小时」这些**当天内**的短间隔，所以没记住的卡片不能直接推到明天。

- **没答对**（不认识 / 拼错 / 听写写错 / 拼音拼错，或"有点模糊"）→ 这张卡**当场插回当日队列**，隔 3 张再出现；
- 再次出现仍没答对 → 继续插回，**直到答对为止**，当天的练习不会在还有未掌握卡片时结束；
- 答对后才离开当日队列，复习日固定在**明天**，且**不因为当天反复答对而升级阶段**（避免一天之内把记忆阶段刷高）；
- 新卡第一次就答对，也会在当天再出现一次，作为「5 分钟节点」的巩固；
- 安全阀：同一张卡当天连续错 5 次（"模糊"2 次）后暂时放过，明天再来，避免卡死；
- **退出即放弃**：练习中点「✕」就结束当天这组（会提示还有几张没学完），已作答的记录都会保存，没记住的明天照常复习。

三档作答：`确实认识`（升级）/`有点忘了`（不升级，当天会再出现）/`不认识`（回到第 1 阶段，当天反复出现直到答对）。

首页「开始今天的学习」= 六项练习的到期复习 + 每日新卡，按科目交叉穿插。
进度页：7 日柱状图、遗忘曲线对比图、9 级记忆稳固度、薄弱卡 Top6、累计答对率、连续打卡。

### 2.4 多档案

首屏建档（名字 + 12 个表情头像 + 年级/教材/英语起点），可随时切换、改名、删档；每个档案的六项练习进度、日志、设置、学习范围完全独立；支持 JSON 备份导出/导入（合并同名档案）。数据只存浏览器本地，不上传。

## 七、本地存档在哪、怎么保证不丢

### 7.1 存档位置

| 项目 | 说明 |
|---|---|
| 存储技术 | 浏览器 `localStorage` |
| 键名 | 主存档 `ebbinghaus.kids.v1`；上一版快照 `ebbinghaus.kids.bak`；元信息 `ebbinghaus.kids.meta` |
| 物理位置（Windows Chrome） | `C://Users//<用户名>//AppData//Local//Google//Chrome//User Data\Default\Local Storage\leveldb\` |
| 物理位置（Windows Edge） | `C://Users//<用户名>//AppData//Local//Microsoft//Edge//User Data\Default\Local Storage\leveldb\` |
| 能不能直接拷 | **不能**。这是 LevelDB 二进制库，必须用 App 内「我的 → 导出备份」生成 JSON |

要点：
- 同一台电脑的**不同浏览器互不相通**（Chrome 学的和 Edge 学的各存一份）；
- 同一浏览器的**不同用户账户/不同 Profile** 也不相通；
- **无痕模式**关窗即清空；
- 用 `file://` 双击打开时，数据属于 `file://` 这个来源，和用 localhost 打开是两份数据——**别混着用**。

### 7.2 七层防丢机制（v1.3.2 起）

| 机制 | 作用 | 触发时机 |
|---|---|---|
| **① 固定 key + 版本迁移** | 程序升级永远读写同一个 key，靠内部 `v` 字段与迁移函数升级结构，不会"换了版本就找不到老存档" | 每次启动读取 |
| **② 上一版快照** | 每次保存前把旧内容另存到 `...bak`（60 秒节流），误操作/写坏时可回退 | 每次保存 |
| **③ 损坏隔离** | 主存档 JSON 解析失败时，把原文另存为 `...v1.corrupt.<时间戳>`，然后自动尝试快照，**绝不静默清空** | 启动读取失败 |
| **④ 高版本只读保护** | 用旧版程序打开新存档（v 更高）时进入只读，不覆盖、不降级 | 启动检测 |
| **⑤ 导出提醒 + 导入前快照** | 超过 30 天没导出会在「我的」页弹提示；导入备份前先留一份快照 | 打「我的」页 / 导入时 |
| **⑥ 多标签页同步** | 另一个标签页改了进度会自动同步，避免两个窗口互相覆盖 | `storage` 事件 |
| **⑦ 数据指纹** | 对「档案名+模块+卡片+阶段+复习日」排序后算 32 位哈希，迁移/导入前后对比即可确认数据一字不差 | 「我的 → 存档」实时显示 |

「我的 → 存档」里能直接看到：存储方式、存档版本、读取来源（主存档/快照）、档案数、卡片数、上一版快照时间、上次导出时间，以及一个「从上一版快照恢复」按钮。

### 7.3 换浏览器 / 换电脑怎么搬（Edge → 360 极速 等）

**不能拷浏览器文件夹**，用 App 自带的导出/导入，3 步：

1. **旧浏览器（Edge）**：打开 `记忆小站.html` → 我的 → **导出备份** → 得到 `记忆小站备份-2026-10-25.json`；
2. **新浏览器（360 极速）**：把同一个 `记忆小站.html` 用 360 打开（右键 →「打开方式」→ 360 极速浏览器）；
3. 欢迎页直接点 **「从备份导入（换浏览器/换电脑）」** → 选第 1 步的 json。
   若已经建过空档案，也可以走「我的 → 导入备份」，效果一样。

同名档案会**合并**（不会重复新建），导入提示会显示"1 个档案 / N 张卡片"，可以和旧浏览器「存档」里的卡片数核对。

App 里「我的 → 存档」会显示**当前浏览器名称**（Edge / 360 极速 / Chrome…），一眼就能确认自己有没有在正确的浏览器里操作；
旁边还有「换浏览器 / 换电脑？」按钮，把上面三步直接展示出来。

> **更省事的方式**：`_tools/build-migration-page.mjs` 能生成一个「一键迁移」页面——把你导出的备份 JSON 内嵌进去，
> 用目标浏览器打开一次就自动合并写入，页面上直接显示迁移前后的档案数、卡片数和数据指纹，方便核对。
>
> 为什么不能直接拷文件夹：`Local Storage\leveldb` 是 Chromium 的二进制库，里面**混着这个浏览器所有网站的数据**，键名带 origin 哈希；
> 不同浏览器/版本的 LevelDB 格式不保证兼容，硬拷轻则读不出，重则把新浏览器里其它网站的数据搞坏。json 导出才是跨浏览器的稳定通道。

### 7.4 家长该怎么做

1. **每月导出一次**：我的 → 导出备份 → 得到一个 `记忆小站备份-日期.json`，丢进网盘或发自己微信收藏；
2. **换电脑/换浏览器前**一定先导出，新环境里「导入备份」即可（同名档案会合并，不会重复）；
3. **别点「清除浏览数据 / 清除缓存和网站数据」**，一清就没了（App 内的快照也在同一处，一起没）；
4. 孩子在同一台电脑上继续用**同一个浏览器**，进度就是连续的。

### 7.5 已知边界

- 浏览器清数据、换设备、系统重装 → 本地存档必失，只能靠导出的 JSON 恢复；
- `localStorage` 每个来源约 5MB，当前一个孩子一年的记录约 20–60KB，够用很多年；
- iOS 上如果**发布成网站**访问，Safari 的 ITP 可能清理 7 天未访问站点的可写存储——所以网页版更要靠"导出/云端同步"（见下一节）。

### 8.3 发新版时用户会不会丢数据

不会。三条保障：

1. **数据与代码分离**：档案存在云端 `kid_profiles` 表里，发布新版只替换静态文件，表不动。
2. **数据结构有版本号**：`store.js` 的 `SCHEMA` + 迁移链，老结构自动升级，不需要用户手动处理。
3. **发布复用同一个应用 ID**：域名不变 → 云端 Origin 校验不变 → 用户原来的登录态继续有效。

操作方式：改完代码执行 `node _tools/build-single.mjs`，然后重新发布同一个目录即可，链接不变。

## 九、关键决策记录

1. **不 fork 现有项目**：最接近的两个无许可证、两个 GPL/AGPL，二次开发有法律风险；改为借鉴思路 + 自研。
2. **不做桌面/APP 包**：整站 1MB、无依赖无构建，网页形态已够用；将来要 APP 可用 Capacitor/Tauri 包一层（已按 PWA 规范写好 manifest 与离线缓存）。
3. **间隔用「天」**：家长通常每天陪练一次，日粒度更贴近真实使用；组内即时巩固弥补同日短间隔。
4. **作答只有三档**（而非 SM-2 六档）：小学生分辨不出"困难/勉强"，`认识/不认识` + 一次二次确认足够。
5. **当天必须练到认识为止**：艾宾浩斯的复习节点包含当天内的短间隔，把没记住的卡直接推到明天等于漏掉了最关键的巩固窗口；因此答错的卡会插回当日队列循环，答对方可离开。同时「当天重复答对不升级阶段」，避免一天内把同一张卡刷到高阶段造成虚假掌握。
5. **认词/拼写、认字/听写、认读/拼写各自独立记录**：同一内容"看得懂"和"写得出"是两种能力，共用词库但进度分开（所以"每日新卡"按每项练习计）。
6. **拼音与英语同构**：不另造一套交互，直接把"看英文说中文"换成"看拼音说例字"，孩子和家长不用重新学一遍操作。
7. **拼音拼写引入声调选择器**：键盘打不出 ā/á/ǎ/à，所以字母用输入、声调用点选；字母对但声调错判"差一点"，不直接判错。
8. **中文按使用频率分组**（而非教材册次）：没有可靠的教材分册数据源，频率排序能让第 1 组就是最该先掌握的字。
9. **教材作为配置项 + 匹配说明**：只有一套按课标整理的词库，选其它版本时按同年级通用内容匹配，UI 明说，不假装有分版本词库。
10. **释义去字源清洗**：字典原文是《说文》风格，脚本剔除字形/通假/姓氏片段，优先取现代义项。

## 十、已知限制 / 待定事项

- **朗读**依赖浏览器内置语音（Windows 中文 Huihui/Xiaoxiao、英文 Zira）；装了高质量语音包会自动优先本地音色。
